# OctoAcme Project Management Documentation

## Purpose

This README provides a single entry point to the OctoAcme project management documentation and a brief summary of the core processes used by the project. Each linked document contains detailed guidance, templates, checklists, and best practices for its respective process.

## OctoAcme Project Management Overview

OctoAcme follows a structured, iterative approach to project management grounded in these core principles:

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named Project Manager and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

### Core Project Lifecycle

OctoAcme projects follow a standardized five-phase lifecycle:

1. **Initiation** — Define the business need, success criteria, stakeholders, and high-level timeline. Create a Project One-pager and obtain stakeholder alignment before moving forward.

2. **Planning** — Break work into shippable increments, establish a prioritized backlog with acceptance criteria, identify dependencies and risks, and define milestones and release plans.

3. **Execution & Tracking** — Execute planned work in sprints or cycles, track progress on a project board, conduct daily standups and weekly syncs, run quality checks (unit tests, integration tests, code reviews), and escalate blockers.

4. **Release & Deployment** — Verify pre-release readiness, execute deployment checklists, conduct smoke tests, and maintain rollback plans for production safety.

5. **Retrospective & Continuous Improvement** — Conduct retrospectives after milestones or releases, capture learnings, and iterate on process improvements.

### Key Roles & Responsibilities

- **Product Manager** — Defines outcomes, prioritizes the backlog, validates solutions, and measures success
- **Project Manager** — Coordinates delivery, manages schedules, risks, and communications; ensures transparency and alignment
- **Developers** — Implement features, write tests and documentation, participate in design and code reviews, assist in estimation and planning
- **QA/Testing** — Validates quality against acceptance criteria and conducts manual acceptance testing where needed
